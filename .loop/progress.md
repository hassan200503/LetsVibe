## Iteration 015 - 2026-11-18 - AI safety and citation quality (E7-004)

- Added `src/lib/research/safety.ts`: retrieved study abstracts and web snippets are wrapped in a labelled fence whose body has every run of two or more `<` rewritten, so quoted text cannot forge the closing marker; the system prompt carries the matching "data, never instructions" rule.
- Crisis routing is sentence-scoped and needs first-person evidence (self-harm signals plus `I/my/we`, or being hit/threatened/abused), so "what do domestic-violence statistics say" is answered normally while "he hits me most nights" is not. A crisis match short-circuits before the key, quota and model calls, streams a `safety` event with external resources and writes nothing but metadata to the log.

## Iteration 023 - 2026-11-19 - Sync protocol with a measurable drift harness (E5-013)

- The room's sync logic was good but only existed inside `room-provider.tsx`: untestable, unmeasurable, and the drift target ("p95 under 500 ms") was a sentence rather than a number. It is now `packages/sync-protocol`, a dependency-free TypeScript package the web app imports - and the one place the clock and correction rules live.
- `clock.ts`: a sample is `{sentClientMs, receivedClientMs, serverTimeMs}`; the offset comes from the **fastest** round trip among the last 12 (the least delayed estimate, since queueing can only add delay) and `serverNow` converts local time. `state.ts`: `applyEvent` drops `seq <= state.seq`, so a replayed or reordered snapshot is a no-op rather than a jump - idempotent handlers without a queue. `expectedPositionMs` is `positionMs + (now - serverTimeMs) * rate`, clamped at zero.
- `correction.ts`: one function decides hold / nudge / seek - `<150 ms` leave it alone, `150-1000 ms` shift rate by up to 5% (10% while catching up after a stall), `>=1000 ms` or a player without rate control seeks. `heartbeatDue` is 5 s. The thresholds from the PRD are constants, asserted in tests, not comments.
- `simulator.ts`: two clients with skewed clocks (+37 s / -12 s), imperfect media clocks (+0.12% / -0.09%), six bootstrap pings, 500 ms ticks, 1 s polls, a server that owns `seq`, and a network with latency, uniform jitter per message, loss, and retrying/deduped controls. Virtual time steps 25 ms; nothing calls `Date.now()` or `Math.random()` (mulberry32), so the same seed replays the same numbers and a regression fails CI instead of flaking. Buffering is modelled as a player clock that freezes (B 650 ms at 20 s, A 2.5 s at 50 s); drift samples within a 2 s settle window after a seek or stall are excluded from p50/p95 but still counted in `worstMs`, which is reported rather than asserted.
- Measured, seed 7, 95 s scenario (source, play, 60 s seek, pause, play): **wifi p50 13 / p95 295 / max 559 ms; mobile p95 280; poor p95 326** - every profile under the 500 ms p95 target, with 5 seeks and 29-30 rate nudges (i.e. the correction loop is doing the work, the seeks are the three deliberate seeks plus the two post-stall recoveries). At **33% loss** p95 is 286 ms with delivery recovered and missed broadcasts counted. A separate test asserts a seek's spike is visible in `worstMs` while p95 stays clean, so the two numbers cannot silently swap meaning.
- The web app now consumes the package: `room-provider.tsx` builds its clock with `addSample`/`estimateClock`, its expected playhead with `expectedPositionMs` (room state is seconds at `updatedAt`, rate 1), and its decision with `planCorrection`, passing `hardMs` 1 s or 1.6 s depending on whether the player can rate-shift. `overCount`, `canJump`, the 1.5 s/slow-line seek backoff and all buffering checks are untouched - this iteration shares the math, it does not change when the app jumps.

## Iteration 027 - 2026-11-19 - Gate-failure triage and repair plans (E17-003)

- The maintenance half of E17 now has a second tool: `pnpm triage:agent` (`scripts/agent-triage.mts`) turns one saved gate log into an ordered repair plan. With no arguments it takes the newest `.loop/logs/*.log`; `--log <file>` points at another log; `--run typecheck|lint|test|build|a11y` runs exactly one allowlisted root gate first. It writes `triage-<stamp>.md` and `latest.md` under `.loop/triage/`, refuses any `--out` outside `.loop/`, never runs git and exits 0 once a report exists (2 only for a usage or read error), so it cannot break a pipeline or fake a pass.
- The parser is pure TypeScript in `apps/web/src/lib/agent/triage.ts`. It strips ANSI and turbo package prefixes, then recognises: `file(line,col): error TSxxxx`; ESLint `file:line:col error message  rule`; Vitest `FAIL file > test` plus the next `AssertionError`; a Next `./file:line:col` line followed by `Type error:`; and axe route counts with `[severity] rule: message` lines. Absolute paths printed by turbo or ESLint are anchored back to `apps/web/` or `packages/<pkg>/` before display, so the report does not leak a developer's home directory and file existence checks work.
- The plan is ordered, not a dump: compile/build failures first (rank 1), then lint (2), tests (3), a11y (4), unknown (5); ties sort by file and line, and repeats are deduped on gate/file/line/rule/message. Every failure carries a hint specific to its code or rule where one is known (TS2345/2322/2307/18048/2339, no-explicit-any, exhaustive-deps, rules-of-hooks, no-img-element, focused-test and axe guidance) and a proof command: the package-filtered gate for compile/lint/build, `pnpm --filter @lovora/web exec vitest run <file>` for a failing test, `pnpm a11y` for axe. When there is at least one failure a final step runs the full gate set.
- The tool says "I don't know" rather than guessing. An empty log, a truncated log with no failure line, a failed test summary whose `FAIL` line was cut, or a `Failed to compile` with no location each produce a note and `unknown` status (or a generic build finding); a referenced file that no longer exists is marked **stale reference** with a re-run instruction. On a clean recognised log the status is `clean`. The CLI smoke tests covered both ends: the synthetic log with one TypeScript error, one ESLint error and one failing test produced three ranked failures with the expected package, file, line, rule and proof commands; `--run typecheck` on the real tree produced status `clean`, exit 0.
